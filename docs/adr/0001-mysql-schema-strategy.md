# ADR-0001：MVP MySQL 表结构策略

## 状态

已采用。

## 背景

FlowOps 第一版需要体现多租户隔离、RBAC、工单状态机、SLA、审计以及可靠消息，同时项目也是维护者学习 Spring Boot 企业开发的载体。数据库设计需要保留真实业务约束，但不能提前演变为通用工作流或复杂组织平台。

## 决定

- 使用 MySQL 8、InnoDB、`utf8mb4` 和 `DATETIME(3)`。
- 主键使用 `BIGINT UNSIGNED`，租户业务唯一索引以 `tenant_id` 开头。
- 状态使用 `VARCHAR` 代码值，领域层使用 Java 枚举约束。
- MVP 使用逻辑外键，不使用级联删除。
- 用户只属于一个主部门；历史工单保存创建部门快照。
- 工单类型暂用代码枚举，不建立配置化工作流表。
- 用户、部门、角色采用禁用状态，工单与流水记录不删除。
- 工单主表保存当前状态快照，流转和分派表保存完整历史。

## 备选方案

- 使用 MySQL `ENUM` 或数字码保存状态。
- 为全部引用建立物理外键及级联规则。
- 从第一版支持用户多部门关系。
- 从第一版建立工单类型、字段定义、状态定义和流程边配置表。
- 对所有表统一使用 MyBatis-Plus 逻辑删除。

## 后果

优点是表结构直观、便于 Navicat 排查，Java 映射简单，能够优先完成核心工单闭环。代价是引用完整性主要依赖应用服务、数据库唯一约束和自动化测试；未来增加多部门、可配置流程或外部通知渠道时，需要增加关联表和迁移脚本，而不是直接复用当前字段完成全部需求。
